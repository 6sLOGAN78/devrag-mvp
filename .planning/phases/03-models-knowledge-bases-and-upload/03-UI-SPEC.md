| Role | Value (light / dark) | Usage |
|------|----------------------|-------|
| Dominant (60%) `--background` | `#FFFFFF` / `#0B0F14` | Page content, input and textarea fill, dropzone fill, read-only model list rows |
| Secondary (30%) `--card`, `--muted` | `#F1F5F9` / `#131A22` | Header, sidebar, cards, dialog surface, table header row, dataset cards |
| Border `--border`, `--input` | `#E2E8F0` / `#243040` | Card outline, dividers, dropzone dashed border at rest, progress bar track |
| Accent (10%) `--primary` | `#0F766E` / `#2DD4BF` | Reserved list below |

| Success `--success` | `#15803D` / `#4ADE80` | Status only, always with a text label: "Configured" provider badge, "Uploaded" file-row icon, sonner success stripe |

`--card` and `--muted` are the same colour. Anything that sits on a dialog or card surface and needs to be told apart from it uses `--background` (dropzone fill, read-only rows) or `--border` (progress track), never `bg-muted`.

Accent reserved for, and nothing else in this phase:

1. The single primary button of a view or dialog: "Create dataset", "Upload files" (workspace header or empty state), "Upload {n} files" and then "Done" in the upload dialog, "Test and save" in the provider dialogs, "Save defaults", "Save settings", "Open model settings" in the missing-default dialog.
2. Focus ring on every interactive element.
3. Active navigation item: leading bar and icon.
4. Inline text links: "Datasets" back link, "Open model settings" in the gallery notice, "Clear search".
5. Progress bar fill (reserved since Phase 1).
6. The dropzone border while a valid file drag is over it (2px solid accent instead of dashed border colour).

Accent is never used for: dataset card borders or hover, badges, the current-workspace check mark (foreground), status icons, selected radio dot (foreground), table row hover (`--background` on card surface).

One primary per view: repeated row actions ("Set up", "Add model", "Change key", row delete, file-row "Remove", "Try again") are `outline` or `ghost`. The model settings page has exactly one primary on the page ("Save defaults"); a dialog's primary exists only while the dialog is open and the page behind is inert.

Destructive fill appears only on the confirm button inside an `AlertDialog`.

## Workspace selector (D-26)

### Placement and anatomy

Lives in the `StandardLayout` header, left cluster, directly after the wordmark, separated from it by a vertical `Separator` (24px high). **(auto-selected: the active workspace is global context for several pages; the header is the only chrome visible at every breakpoint, including the 64px rail and the mobile layout.)** Below 640px the wordmark text is hidden in the header (`hidden sm:inline`; it still titles the mobile sheet) so the selector fits at 320px.

Component `WorkspaceSwitch` (`components/workspace-switch.tsx`):

- Trigger: `ghost` button, height 40px: `Building2` icon (16px, muted) + workspace name (Body 600, `truncate`, max width per Spacing) + `ChevronsUpDown` (16px, muted). `aria-label`: "Workspace: {name}. Change workspace". `data-testid="workspace-switch"`.
- When the caller belongs to only their own workspace: the same icon and name render as plain text with a visually hidden prefix "Workspace:", not a button. No menu with a single entry.
- Menu (`DropdownMenu`, min width 240px, `align="start"`): caption "Workspaces" (Label, muted); one item per workspace with `role="menuitemradio"` and `aria-checked`; then a `Separator` and the item "Manage team" linking to `/user-setting/team`.
- Item anatomy: line 1 workspace name (Body); line 2 (Label size, weight 400, muted) "Owner" for the caller's own workspace, otherwise "{role} · Owned by {owner}". The current workspace shows a trailing `Check` icon in foreground colour. `data-testid="workspace-option-{tenantId}"`.
- Order: the caller's own workspace first, then joined workspaces by name (locale-aware compare).

### Data and state

- Source: the caller's own workspace from the user store (`tenantId`, `tenantName`, role `owner`) plus `GET /v1/tenant/list` (the hook the Team page already uses), keeping entries whose role is `admin` or `normal`. Role `invite` is never listed.
- Store: Zustand `stores/workspace-store.ts` holding `activeTenantId`. Derived selectors give the active name and the caller's role in it. Persisted in `localStorage` key `devrag.workspace` as `{ userId, tenantId }`; a stored value for another user id is ignored. Default is the caller's own workspace.
- While the list is loading the header shows the own workspace as plain text and upgrades to the button when a joined workspace arrives. A failed list request leaves the header on the own workspace with no error UI in the header (the Team page reports list errors).
- Every workspace-scoped query key starts with `["ws", tenantId, ...]`, and every request for a route that has no resource id (`GET/PUT /providers`, `GET /models`, `GET/PATCH /models/default`, `GET/POST /datasets`) sends the active `tenant_id` explicitly (RESEARCH Pattern 7).

### What changes on switch

| Thing | Behaviour on switch |
|-------|---------------------|
| Header label | Shows the new workspace at once; focus stays on the trigger |
| Announcement | A visually hidden `role="status"` region says "Switched to {workspace}". No toast (the header already shows the change) |
| Datasets gallery | Lists the new workspace's datasets; `page` and `keywords` reset |
| Model settings | Shows the new workspace's providers and defaults; edit rights follow the caller's role there |
| Dataset workspace (`/dataset/files`) | The open dataset belongs to the previous workspace: navigate to `/datasets` (replace) |
| Open dialogs | Cannot occur: dialogs are modal and the header is inert while one is open |
| Home, Profile, API tokens, Team, System status | Unchanged. They describe the user and the user's own workspace (Phase 2) **(auto-selected: keeps Phase 2 pages and their tests untouched)** |
| Cached data | Nothing is invalidated; queries for the previous workspace stay cached under its key |

Other rules:

- Deep link: opening `/dataset/files?id=...` for a dataset in another joined workspace sets the active workspace to the dataset's `tenant_id` silently (plus the hidden announcement), so the header always names the workspace the page belongs to.
- Lost access: if the active workspace is no longer in the list (removed by the owner, or a workspace-scoped request answers the not-found envelope for the tenant), fall back to the own workspace and show an info toast "You no longer have access to {workspace}" / "Switched to your own workspace." When the caller left it from the Team page in this tab, fall back without the extra toast.
- A 403 on a mutation (role changed while the page was open): inline `Alert` in the dialog or page, "You don't have permission to do that in {workspace}. Your role may have changed.", and refetch the workspace list. Never a session toast.

## HTTP client rules for this phase

| Request | Client timeout | `silent` | Notes |
|---------|----------------|----------|-------|
| Default (lists, detail, defaults, settings update) | 10s (existing `TIMEOUT_MS`) | no for queries rendered through `ErrorState`: they pass `silent: true` and render in place; mutations in dialogs pass `silent: true` and show an inline `Alert` | Unchanged client |
| Test and save a provider, add a model | 45s per request | yes | The server test call has its own 20s limit (RESEARCH Pitfall 8) |
| Create dataset, delete dataset | 30s | yes | Index provisioning and index cleanup can exceed 10s on a loaded host **(auto-selected)** |
| Upload one file | **none** (`timeout: 0`) | yes | Cancelled only through an `AbortController`; progress from `onUploadProgress`. A 100 MB file on a slow link takes minutes; a fixed client timeout would cut it |

**A provider refusal is never a session event.** The server answers a rejected key, model or base URL with HTTP 400 and a sanitized reason, never 401 and never envelope code 401 (RESEARCH Pitfall 7). The SPA shows that reason inline in the dialog. The shared interceptor is not changed and gets no bypass flag, because a real 401 on these routes must still end the session. Copy for provider failures never uses the words "session", "sign in" or "unauthorized". A live test submits a bad key and asserts: the user is still on `/user-setting/model`, the stored token is unchanged, no "Session expired" toast exists, and the dialog shows the refusal.

Server messages shown inline use the existing rule (non-empty string, shown as returned) with a limit of 300 characters for provider refusals (the server truncates the provider's reason to 200) and 160 elsewhere; longer or empty messages use the fallback copy.

## Screen: Model settings (`/user-setting/model`) — UI-37

Focal point: the "Providers" card title and its status badges; then "Default models".

Structure: `PageHeader` "Models" (no header action). Helper line under the title (Body, muted): "Model providers and default models for {workspace}." Then, stacked with 24px gaps:

1. Read-only notice (members only): `Alert variant="info"`: "Only the workspace owner and admins can change model settings."
2. "Providers" card.
3. "Default models" card.

### Providers card

A list (`<ul>`, dividers between rows), one row per provider in this fixed order (D-15): OpenAI, Azure OpenAI, Ollama, OpenRouter, OpenAI-compatible. Owner and admin see all five. Members see only configured providers.

Row anatomy (stacks vertically below 640px):

| Part | Content |
|------|---------|
| Title line | Provider name (Body 600) + status `Badge`: "Configured" (`success` variant, `CircleCheck` icon) or "Not configured" (`default` variant) |
| Description | One line, Body muted (copy table) |
| Credential line (owner and admin, configured only) | "API key" (Label) + mono `••••••••ab12`; then, when the provider has one, "Base URL" (Label) + mono URL, `break-all`. Ollama shows only the base URL. Members never see this line: no mask, no last 4, no URL |
| Models | Compact list under the row: model id (mono 14px, `break-all`), type badge "Chat" or "Embedding" (`default`), for embedding models "{dim} dimensions" (Label size, 400, muted, `tabular-nums`), and an `outline` badge "Default chat" or "Default embedding" on the workspace default |
| Actions (owner and admin) | Not configured: `outline` button "Set up". Configured: `outline` "Add model", `ghost` "Change key" ("Change address" for Ollama), `ghost` icon button `Trash2` |

Accessible names include the provider: "Set up {provider}", "Add a model to {provider}", "Change the key for {provider}", "Delete {provider} credentials".

### Provider dialog: set up

`Dialog` (`max-w-md`). Title "Set up {provider}". Fields by provider:

| Provider | Base URL | API version | API key | Chat model | Embedding model |
|----------|----------|-------------|---------|------------|-----------------|
| OpenAI | not shown (documented default) | not shown | required | optional | optional |
| Azure OpenAI | required, label "Endpoint" | required | required | optional, label "Chat deployment" | optional, label "Embedding deployment" |
| Ollama | required | not shown | not shown | optional | optional |
| OpenRouter | not shown (documented default) | not shown | required | optional | optional |
| OpenAI-compatible | required | not shown | optional | optional | optional |

At least one of the two model fields must be filled (form-level rule, error under the second field). Helpers: model fields "The model id exactly as the provider names it, for example {example}." (OpenRouter examples `meta-llama/llama-3.1-8b-instruct` and `baai/bge-m3`; other providers use their own documented example); Ollama base URL "The server address without /v1, for example http://localhost:11434."; OpenAI-compatible key "Leave blank if the service needs no key."

Client validation (mirrors the server, which stays authoritative): base URL is a full `http://` or `https://` URL with no user name, password or fragment; Ollama base URL must not end in `/v1`; model ids are 1 to 128 characters with no whitespace and no `@` (the composite id separator; `/` and `:` are allowed).

Key field: `password-input` (hidden by default, show and hide toggle), `autocomplete="off"`, `spellCheck={false}`, `data-1p-ignore`, `data-lpignore="true"`, field name `provider_key` (not `password`). The typed key lives only in form state: it is cleared on close, on unmount and on success; it never enters the URL, a query key, a toast, a log line or the persisted mutation cache (`gcTime: 0` and `reset()` after settle).

Footer: `ghost` "Close" and primary "Test and save" (D-16).

Submit behaviour:

- While pending: button `aria-disabled` and `aria-busy` with `Loader2`, label unchanged; fields become read-only; a `role="status"` line under the fields says "Testing the connection with a small request. This can take up to 30 seconds." The dialog cannot be dismissed by overlay click while pending; Esc and "Close" abort the request (nothing is saved because the server stores only after a passing test).
- Refused (HTTP 400): destructive `Alert` above the footer. Title line (Body 600) "{provider} refused this configuration", then the provider's reason as returned by the server; fallback "Check the key, the base URL and the model ids, then try again." Nothing was saved; the form keeps its values (the key included, still hidden) and focus moves to the Alert (`tabIndex=-1`).
- Rate limited (HTTP 429): Alert with the server message; fallback "Too many tests in a short time. Wait a moment and try again."
- Provider slow or unreachable (HTTP 503 or 504, or client timeout): Alert "The provider didn't answer in time. Nothing was saved. Try again."
- Not permitted (HTTP 403): Alert with the lost-permission copy from the workspace section.
- Success: dialog closes, focus returns to the row, toast "{provider} saved". When the workspace still lacks a default for a model type just added, the toast description is "Choose default models below so datasets and chat can use them."

### Provider dialog: change key

Title "Change the key for {provider}" ("Change the address for {provider}" for Ollama). Fields: base URL and API version where the provider has them (prefilled, editable; they are not secret) and the API key (empty, required for OpenAI, Azure OpenAI and OpenRouter; optional for OpenAI-compatible). Helper under the key: "The saved key ending {last4} is replaced. A saved key can't be shown again." (D-17). For OpenAI-compatible: "Leave blank if the service needs no key. A saved key is never reused with a new address."

Rule for the planner (security): the saved key is never sent to a different base URL. A change of base URL without a newly typed key must be refused by the server as well as by the form. The test uses one of the provider's registered models. Footer, pending, refusal and success behaviour as in set up; success toast "{provider} updated".

### Add model dialog

Title "Add a model to {provider}". Fields: "Model id" and "Type" (`native-select`: "Chat", "Embedding"). Primary "Test and save". The server tests the model with the saved credentials and records the embedding dimension. Same pending, refusal and success pattern; success toast "Model added". There is no per-model remove in this phase: the docs define no route for it; a mistyped model is never stored because the test fails **(auto-selected)**.

### Delete provider credentials

`AlertDialog`:

- Title: "Delete {provider} credentials?"
- Body: "The saved credentials and the {count} models from {provider} are removed from {workspace}. Default models that come from {provider} are cleared, and datasets that use its embedding model can't index new content until you add it again. This can't be undone."
- Buttons: "Keep provider" (dismiss, default focus) and "Delete provider" (destructive). Success toast "{provider} credentials deleted"; focus moves to the Providers card title. A server refusal is shown as an error toast with the server message.

### Default models card (D-18, TEN-12)

Title "Default models". Owner and admin see a form (`max-w-md`):

- "Default chat model": `LlmSelect` filtered to chat models.
- "Default embedding model": `LlmSelect` filtered to embedding models. Helper: "New datasets start with this model. Existing datasets keep the model they were created with."
- Each select has a first option "Not set" (empty value), which is what is selected until someone chooses; nothing is preselected or guessed. A saved default whose model no longer exists shows "Not set".
- No model of a type yet: the select is disabled with the helper "Add a provider with a chat model first." or "Add a provider with an embedding model first."
- Footer: primary "Save defaults", `aria-disabled` until the form is dirty. Success toast "Default models saved". Errors: inline `Alert` with the server message.

Members see the same two labels as a read-only definition list: the model id in mono, or "Not set" in muted text. No selects, no button.

### States

| State | Treatment |
|-------|-----------|
| Loading | Providers card: five skeleton rows (64px). Defaults card: two skeleton fields. Title and helper render at once |

## Upload dialog (`components/file-upload-dialog`) — UI-12

`Dialog` (`max-w-xl`). Title "Upload files to {dataset}". Description (Body, muted): "PDF, Word, PowerPoint, Excel, text, Markdown, HTML, CSV, JSON, EPUB, JPG, PNG, MP3 or WAV. Up to {size} per file, {maxFiles} files at a time."

Limits and the extension list come from the server (the planner picks the carrier, for example an `upload_limits` object on the dataset detail), with compiled-in fallbacks equal to the RESEARCH defaults: 104 857 600 bytes per file, 20 files per batch, 10 000 documents per dataset, extensions `pdf, docx, pptx, xlsx, txt, md, markdown, csv, json, html, htm, epub, jpg, jpeg, png, mp3, wav`. Image types are `jpg`, `jpeg` and `png` only (D-28). The server remains authoritative; client checks exist to save the user a wasted upload.

### Dropzone (native events, no library)

- A bordered region (`2px dashed --border`, radius 8px, `bg-background`, padding 24px, `min-h-40`), centred content: `Upload` icon 32px (muted), Body "Drag files here, or", `outline` button "Choose files".
- "Choose files" triggers a visually hidden `<input type="file" multiple accept="{extension list}">`. The button is the keyboard path; the region itself is not focusable (`role="group"`, labelled by the dialog title).
- Drag handling: `dragenter` and `dragover` call `preventDefault()` only when `dataTransfer.types` contains `Files`; a depth counter handles nested enter and leave events; `drop` reads `dataTransfer.files`. While a file drag is over the region: border becomes 2px solid accent and the text reads "Drop to add files".
- While the dialog is open, `dragover` and `drop` on `window` are prevented so a drop that misses the region can't make the browser navigate to the file.
- A dropped folder (`webkitGetAsEntry().isDirectory`, or a zero-byte item with no type where that API is missing) is listed as rejected with the folder message.
- When the dataset is already at its document limit the dropzone is replaced by an info `Alert`: "This dataset already holds the maximum of {max} documents. Delete some before uploading more."
- Adding the exact same file again (same name, size and last-modified time) is ignored.

### Client checks, in this order per file

| Check | Row error |
|-------|-----------|
| Folder | "Folders can't be uploaded. Add the files inside it instead." |
| Name longer than 255 characters | "This file name is too long. Rename it to 255 characters or fewer." |
| Extension not on the list (case-insensitive, last extension only, so `a.pdf.exe` is `exe`) | "{ext} files aren't supported." When there is no extension: "Files without an extension aren't supported." |
| Empty file | "This file is empty." |
| Larger than the per-file limit | "This file is {size}. The limit is {max} per file." |

Batch limits (D-13) are applied after the per-file checks, to the files that passed, and reported in one info `Alert` above the list rather than per row:

- More than the batch limit: the first files up to the limit are queued. "You can upload {max} files at a time. {extra} files weren't added."
- Dataset would exceed its document limit: files are queued up to the remaining room. "This dataset can hold {max} documents and has {count}. {extra} files weren't added."

### File list

`<ul>` (max height 320px, scrolls) with one row per file, newest batch last. Row anatomy: state icon (16px), file name (Body 600, `break-all`, `line-clamp-2`), size (Label size, 400, muted, `tabular-nums`), state text (Label size, 400), `progress` bar under the name while uploading, one trailing action.

| State | Icon | State text | Progress | Action |
|-------|------|------------|----------|--------|
| Ready | `File` (muted) | "Ready to upload" | none | `ghost` icon `X`, "Remove {name}" |
| Rejected (client check) | `CircleAlert` (destructive) | the check's message, destructive text | none | "Remove {name}" |
| Uploading | `Loader2` | "{percent}%" | determinate | `ghost` icon `X`, "Cancel upload of {name}" |
| Finishing (all bytes sent, waiting for the server to store the file) | `Loader2` | "Finishing" | bar full, `aria-valuetext` "Finishing" | none |
| Uploaded | `CircleCheck` (`--success`) | "Uploaded" | none | none |
| Uploaded and renamed (D-14) | `CircleCheck` (`--success`) | "Uploaded as {newName}" | none | none |
| Failed | `CircleAlert` (destructive) | mapped message, destructive text | none | `outline` small "Try again" (accessible name "Try uploading {name} again") |
| Cancelled | `CircleSlash` (muted) | "Cancelled" | none | `outline` small "Try again" |

Every state has an icon and a text; none is conveyed by colour alone.

### Upload behaviour

- Uploading starts only when the user presses "Upload {n} files" (n counts Ready rows). **(auto-selected: the user can review rejections and remove files first.)**
- One `POST /api/v1/documents/upload` per file (RESEARCH Pattern 9), two in flight at a time **(auto-selected: keeps per-file progress and bounds server memory and temp disk)**, `timeout: 0`, `silent: true`, an `AbortController` per file.
- Progress comes from `onUploadProgress` (`loaded / total`), capped at 99% until the response arrives; at 100% of bytes the row moves to Finishing.
- Rename notice (D-14): when the name in the response differs from the name sent, the row shows "Uploaded as {newName}" and one info `Alert` appears above the list: "{count} files were renamed because a file with the same name was already in this dataset. Nothing was overwritten." (plural-aware).
- The documents query is invalidated after each successful file so the table behind fills in.
- Footer while idle: `ghost` "Close" and primary "Upload {n} files" (`aria-disabled` when n is 0). While uploading: the primary is busy with the label "Uploading {done} of {total}". When no row is Ready, Uploading or Finishing: the primary becomes "Done" and closes the dialog; failed and cancelled rows keep their "Try again".
- Closing while uploads are in flight (X, Esc, overlay, "Close") opens an `AlertDialog`: title "Stop uploading?", body "{count} files haven't finished. Files that already uploaded stay in the dataset.", buttons "Keep uploading" (default focus) and "Stop uploads" (destructive), which aborts the in-flight requests and closes.
- The dialog never closes by itself, so rename notices and failures are always seen.

Server answers per file:

| Answer | Row text | Queue |
|--------|----------|-------|
| HTTP 400 (extension, type, name, empty) | server message; fallback "The server didn't accept this file." | continues |
| HTTP 413 | "This file is larger than the {max} limit." | continues |
| Limit reached on the server | server message; fallback "This dataset can't take more documents." | remaining Ready rows are marked Failed with the same text |
| HTTP 404 | dialog-level destructive `Alert`: "This dataset no longer exists or isn't shared with you. Nothing more was uploaded." | stops; Ready rows become Cancelled |
| HTTP 403 | dialog-level `Alert`: "You don't have permission to upload to this dataset." | stops |
| Network failure | "The connection was lost. Try again." | continues |
| HTTP 5xx | "The server couldn't store this file. Try again." | continues |
| HTTP 401 with the current token | the normal session-expired flow | ends |

Accessibility: each bar has `aria-label` "Upload progress for {name}". One visually hidden `role="status"` region announces batch-level changes only ("{n} files added", "{n} files weren't added", "Uploading {n} files", "{done} uploaded, {failed} failed"), never each percentage. Focus on open: "Choose files". After adding files focus stays where it was. When the batch ends focus moves to "Done". Removing a row moves focus to the next row's action, or to "Choose files" when the list is empty.

## Accessibility and Quality Floor (additions)

- Workspace menu items are `menuitemradio` with `aria-checked`; the current workspace is also marked by the `Check` icon, not by colour.
- Dataset cards: one link per card (the name); the actions menu is a separate, later tab stop. Card content order in the DOM matches reading order.
- Dialog titles and descriptions always present; `AlertDialog` does not close on overlay click; focus returns to the opener, or to the stated fallback when the opener no longer exists (deleted row, deleted card).
- Tables: `<caption class="sr-only">`, `scope="col"`, row actions named with the document name.
- The `choice-group` is a `<fieldset>` with a `<legend>`; arrow keys move between options (native radio behaviour).
- The key field never has its value in the DOM as text; show and hide follow the Phase 2 `password-input` rules.
- File names, dataset names, descriptions and server messages render as text nodes only. No `dangerouslySetInnerHTML` anywhere in this phase.
- Progress and upload states are exposed through `progressbar` semantics and a single polite status region; no per-percent announcements.
- `prefers-reduced-motion`: no progress-fill transition, no dropzone or overlay fade, static spinner icon.
- Contrast: every new text pair uses inherited tokens (4.5:1 or better). The accent dropzone border and the progress fill meet 3:1 against `--background` and `--border` in both themes.
- The SPA never places a provider key in the URL, the document title, a toast, a query key or `localStorage`. The masked form appears only on the model settings page, for owners and admins.

## Checker Flags (non-blocking, 2026-10-08)

The UI checker approved this contract (no blocking dimension). The planner should apply these:

1. **Single-word CTAs.** "Done" (upload dialog primary), "Close", "Previous" and "Next" have no noun. Give "Done" an accessible name such as "Close upload dialog", as "Set up" and the row "Try again" already have.
2. **Catch-all error for provider dialogs.** Set up, change key and add model cover 400, 429, 503/504/timeout and 403 only. Add a fallback key for 500, 502 and network failure, for example "The configuration wasn't saved. Try again."
3. **HTTP 503 is ambiguous in provider dialogs.** Research uses 503 both for an exhausted provider rate limit (with `Retry-After`) and for a missing server key store. Give the two cases distinct envelope codes, or use neutral copy; "The provider didn't answer in time" is wrong for both.
4. **Two delete failures have no copy.** Delete document declares no failure treatment. Delete provider credentials shows the server message with no fallback. Add both, in the style of `datasets.delete.failed`.
5. **Test duration wording.** `models.testing` says "up to 30 seconds", the client timeout is 45 s and the server test is 20 s per call. A set-up with both a chat and an embedding model may run two tests; align the three numbers.
6. **Missing locale keys.** The sr-only announcements "Uploading {n} files" and "{n} files weren't added", a body for `documents.noMatch`, and the document titles ("Datasets - devRag", "Models - devRag") have no keys. `no-hardcoded-copy.test.ts` will fail on these.
7. **Accent list is incomplete.** The page-level drop overlay's 2px accent border and the primary "Back to datasets" button on the dataset-not-found state are not in the accent reservation list. Add both, or restyle them.
8. **Names differ from RESEARCH.md.** This spec uses `pages/dataset/`, `pages/user-setting/model/`, `use-knowledge-request.ts` and `use-llm-request.ts`, taken from `docs/02-frontend/`. RESEARCH.md sketches other names. Follow this spec, because `docs/` is authoritative.
9. **Stack deviation to record.** `CLAUDE.md` lists `react-dropzone` and `@tanstack/react-table`; this spec uses neither (D-21). Record this in `.planning/DECISIONS.md`.
10. **"Add model" route.** The RESEARCH.md route table has no obvious add-model endpoint (the nearest is `POST /providers/{provider}/instances`). Bind the dialog to a documented route.
