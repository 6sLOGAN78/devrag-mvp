## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> gate -> handler | credential class decides reachability; `tenant_id` is an untrusted selector |
| handler -> provider_service | request bodies carry keys and addresses |
| response -> client | masked views only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12-01 | Elevation of privilege | API-token principal writing provider keys | mitigate | `auth: jwt` rows refuse tokens at the gate (401 in flow and matrix tests); `subject_for` never uses the owner role for tokens |
| T-03-12-02 | Elevation of privilege | member or API token writing keys or reading addresses and last4 | mitigate | `forbid_unless` with `update_llm_keys`; `credentials_visible(scope)` is true only for subjects `owner` and `admin` (a token inherits the owner's role but its subject is `api_token`); flow tests as normal member and as API token, matrix assertion for the token list |
| T-03-12-03 | Information disclosure | enumeration of workspaces or providers by 404 vs 403 vs 400 | mitigate | one not-found body for foreign tenant, unknown provider and unconfigured provider; matrix compares byte for byte |
| T-03-12-04 | Information disclosure | provider key in responses, logs, headers | mitigate | SecretStr request field, no body logging, leak sweep with sentinel and stored envelope |
| T-03-12-05 | Spoofing | provider 401 ending the user's session | mitigate | refusals are 400 `provider_refused`; session-still-valid assertion in the flow test |
| T-03-12-06 | Denial of service | worker starvation by slow provider tests | mitigate | dedicated `provider` executor, 50 s handler cap above the 2 x 20 s service cap, per-workspace limiter from plan 03-10 |
| T-03-12-07 | Tampering | mass assignment through extra body fields | mitigate | `extra="forbid"` on every request model; tenant, creator and counters never accepted |
| T-03-12-08 | Information disclosure | fake provider listening on all interfaces during tests | accept | test-only, ephemeral port, fake responses and fake keys only, closed at fixture teardown |
</threat_model>
