## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> update and delete bodies | field names, ids and the workspace selector are untrusted |
| delete -> shared storage | blobs may be referenced from other datasets |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-18-01 | Elevation of privilege | non-managers renaming, re-sharing or deleting datasets | mitigate | `can_manage_dataset` for every id before any change; flow and integration tests per role (D-09) |
| T-03-18-02 | Information disclosure | admins reaching a private dataset | mitigate | visibility check first; owner and admin get 404 for `me` datasets (D-27) |
| T-03-18-03 | Tampering | mass assignment of tenant, creator or counters through PUT | mitigate | field allow-list in the service and `extra="forbid"` model |
| T-03-18-04 | Tampering | embedding model swap leaving vectors in a different space | mitigate | `embedding_locked` once documents or chunks exist |
| T-03-18-05 | Tampering | deleting a blob still used by another dataset | mitigate | workspace-wide reference count in `release_files`; shared-blob integration case |
| T-03-18-06 | Denial of service | half-deleted datasets when the index is down | mitigate | index first, failure aborts; `data.deleted` reports finished ids; idempotent `delete_idx` |
| T-03-18-07 | Tampering | upload racing a delete | mitigate | both take `kb-upload:{dataset_id}`; post-delete upload is 404 |
</threat_model>
