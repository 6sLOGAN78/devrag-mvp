## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server -> provider | outbound HTTP to a user-chosen base URL carrying the tenant key |
| provider response -> server | untrusted bodies, error text, redirects |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05-01 | Information disclosure | SSRF via base URL and redirect to an internal host | mitigate | validate_base_url on every attempt, no-redirect client, test with a 302 and a metadata address |
| T-03-05-02 | Information disclosure | key text in provider error echo or SDK exception | mitigate | safe_message is the parsed, truncated, redacted provider message only; no `str(exc)`; test with `fake-secret-echo` |
| T-03-05-03 | Denial of service | retry storms and SDK plus own retries multiplying | mitigate | `num_retries=0` and SDK `max_retries=0`; one bounded loop; only 429 and timeouts retry |
| T-03-05-04 | Tampering | caller-supplied generation keys overriding Authorization (`extra_headers`) | mitigate | whitelist drops unknown keys; `extra_headers` is accepted only from server code paths, never from request bodies (documented in the module docstring) |
| T-03-05-05 | Denial of service | 200 MB litellm import in a 768 MB container at startup | mitigate | lazy import inside the driver; subprocess test pins it |
</threat_model>
