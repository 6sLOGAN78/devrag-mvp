# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Mode: `--auto`. Every choice not traceable to CONTEXT.md, RESEARCH.md or `docs/` is marked **(auto-selected, not user-reviewed)**. The user may overturn any of them; record the change in `.planning/DECISIONS.md`.

## Scope of this contract

Phase 1 ships only UI-01 (SPA shell: lazy route table, layout wrappers, served through Nginx) and UI-03 (HTTP client: token injection, envelope unwrap, error toast, 401 purge). There is no login, no feature page, no fake navigation. The contract locks the design-system foundation Phases 2-8 inherit.

Phase 1 user-visible surfaces (exhaustive):

| Surface | Route | Layout | Purpose |
|---------|-------|--------|---------|
| System status | `/` | Standard | Real health of the Go and Python servers read through the ingress. The only real page, and not a fake feature. |
| Not found | `*` | Standard | Honest 404 for every route not yet built (including `/login`, `/datasets`, ...) |
| Route error | error boundary | Standard (falls back to Bare) | Render failures and lazy-chunk load failures |
| Toast host | global | n/a | UI-03 error notifications |

Not in Phase 1: login/registration (UI-06), auth guard (UI-02), 401 redirect target (UI-04), session recovery (UI-07), i18n (UI-42), SSE client (UI-05), any feature page.

## Spacing Scale

Declared values (all multiples of 4). Tailwind default scale already matches; no custom spacing keys are added.

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `1` | Icon gaps, badge inner padding |
| sm | 8px | `2` | Compact element spacing, nav item inner gap |
| md | 16px | `4` | Default element spacing, card padding (compact), header horizontal padding |
| lg | 24px | `6` | Card padding (default), content section gaps |
| xl | 32px | `8` | Layout gaps, page horizontal padding at >=1024px |
| 2xl | 48px | `12` | Major section breaks, empty-state vertical padding |
| 3xl | 64px | `16` | Page top spacing for centered states (not found, fatal error) |

Exceptions (all multiples of 4, declared as fixed layout dimensions, not spacing tokens):

- Header height 56px (`h-14`); full-bleed layout header 56px as well.
- Sidebar width 240px expanded (`w-60`), 64px collapsed rail (`w-16`).
- Minimum interactive target 40px (`h-10`) on pointer devices; 44px (`min-h-11 min-w-11`) for icon-only buttons when `@media (pointer: coarse)`.
- Content max width 1280px (`max-w-screen-xl`) on Standard layout; Full-bleed has none.

## Typography

Exactly 4 sizes and 2 weights (400 regular, 600 semibold). Never 500 or 700. Override shadcn defaults that use `font-medium` / `font-bold` to `font-normal` / `font-semibold` when generating components.

| Role | Size | Weight | Line Height | Tailwind |
|------|------|--------|-------------|----------|
| Body | 14px | 400 | 1.5 | `text-sm font-normal leading-normal` (base size for the whole app: it is a dense data tool) |
| Label | 12px | 600 | 1.5 | `text-xs font-semibold leading-normal` (field labels, badges, table headers, nav section captions) |
| Heading | 20px | 600 | 1.2 | `text-xl font-semibold leading-tight` (page titles, card titles, dialog titles) |
| Display | 28px | 600 | 1.2 | `text-[28px] font-semibold leading-tight` (empty-state / not-found hero only; one per page maximum) |

Rules:

- Tailwind `text-base`, `text-lg`, `text-2xl` and other sizes are forbidden in `web/src` (lint with a `no-restricted-syntax` or a grep gate in the frontend check). Declare `fontSize` in `tailwind.config.ts` as exactly `xs`, `sm`, `xl`, `display` so unlisted sizes do not compile to anything.
- Numbers in tables and status values use `tabular-nums`.
- Monospace (same 14px/12px sizes) only for IDs, error codes, route paths, request IDs.

## Color

Dark and light are both defined now as HSL CSS variables on `:root` and `.dark` (shadcn convention, consumed through `hsl(var(--x))`). Identity is a deep teal accent on cool slate surfaces: devRag's own look, deliberately not RAGFlow's blue/white (auto-selected, not user-reviewed).

Theme behaviour: default follows `prefers-color-scheme`; user choice (light / dark / system) is persisted in `localStorage` key `devrag.theme`; `class="dark"` is applied to `<html>` by an inline pre-paint script in `index.html` to avoid a flash. Toggle lives in the header (dropdown-menu with three items).

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) `--background` | `#FFFFFF` | `#0B0F14` | Page background, content area |
| Foreground `--foreground` | `#0F172A` | `#E6EDF3` | Body text (contrast >= 15:1 light, >= 14:1 dark) |
| Secondary (30%) `--card` / `--sidebar` / `--muted` | `#F1F5F9` | `#131A22` | Sidebar, header, cards, skeleton base, table header rows |
| Border `--border` / `--input` | `#E2E8F0` | `#243040` | Dividers, card outlines, input borders |
| Muted text `--muted-foreground` | `#475569` | `#9AA7B4` | Secondary copy, captions (>= 7:1 light, >= 7:1 dark on dominant) |
| Accent (10%) `--primary` | `#0F766E` | `#2DD4BF` | See reserved list (white text on light accent is 5.5:1; `#04201D` text on dark accent is >= 9:1) |
| Accent foreground `--primary-foreground` | `#FFFFFF` | `#04201D` | Text/icons on accent fills |
| Destructive `--destructive` | `#B91C1C` | `#F87171` | Destructive actions and error states only (white on light destructive 6.5:1; dark uses `#2A0A0A` text) |
| Success (status only) `--success` | `#15803D` | `#4ADE80` | "Healthy" status badge dot/text only. Adds one token beyond the template's destructive-only rule because health needs a positive state (auto-selected, not user-reviewed) |

Accent reserved for (and nothing else):

1. Primary button fill (one primary action per view).
2. Focus ring (`--ring` = accent, 2px, 2px offset) on every interactive element.
3. Active navigation item: 2px leading indicator bar and icon color (text stays foreground).
4. Inline text links (underlined on hover).
5. Determinate/indeterminate progress indicators (later phases; reserved now).

Accent is never used for: card backgrounds, headings, toast backgrounds, icons in general, badges, hover fills (hover uses `--muted`).

Toast colors: neutral card surface (`--card`, `--border`) with a 4px leading stripe: destructive for errors, success for confirmations, `--muted-foreground` for info. No full-color toast backgrounds.

60/30/10 check: dominant surface fills the content area, secondary fills sidebar + header + cards, accent appears only in the reserved elements above.

## Layout Shell

Three layout wrappers, each a component under `web/src/layouts/` rendering `<Outlet />`; routes declare which wrapper they use (UI-01: "standard with header, full-bleed for canvas"; docs/02-frontend/routing.md).

### 1. `StandardLayout`

```
+--------------------------------------------------------------+
| Header 56px: [menu*] devRag wordmark      ... theme toggle    |
+----------+---------------------------------------------------+
| Sidebar  | <main id="main"> max-w 1280, p-6 (lg) / p-8 (xl)  |
| 240/64px |   page title (Heading) + body                     |
| nav      |                                                   |
+----------+---------------------------------------------------+
* menu button only below 768px
```

- Header: `--card` background, 1px bottom border. Left: wordmark text "devRag" (Heading size, 600; no logo asset in Phase 1, never an invented mark). Right: theme toggle (icon button, `aria-label="Change theme"`). A user menu slot is reserved but renders nothing until Phase 2 (no placeholder avatar).
- Sidebar: `--card` background, 1px right border. Contains `<nav aria-label="Primary">`. Items are generated from the route registry (below). Label size caption "Platform" above the group.
- Breakpoints: `>= 1024px` sidebar expanded 240px; `768-1023px` collapsed 64px rail with tooltips for labels; `< 768px` sidebar hidden, opened from the header menu button as a left `Sheet` with focus trap and `Esc` close.
- Skip link "Skip to main content" is the first focusable element, visible on focus.
- `<main>` is the only scroll container for content; header and sidebar stay fixed.

### 2. `FullBleedLayout`

Header (56px, same as Standard, no sidebar) plus `<main>` filling the remaining viewport (`h-[calc(100dvh-56px)]`, no padding, no max width, `overflow-hidden`; the child owns scrolling). For Phase 7 canvas and Phase 5 shared chat. Phase 1 builds and tests the wrapper (rendered in the vitest harness through a test-only route; no production route uses it yet).

### 3. `BareLayout`

No chrome. Centered content on `--background`, used for login (Phase 2), public share pages and as the fatal-error fallback if the layout itself fails. Built in Phase 1 because the error boundary needs it.

### Route registry and navigation (no fake features)

Single typed registry `web/src/constants/routes.ts`: each entry `{ path, layout: 'standard' | 'fullBleed' | 'bare', auth: 'none' | 'required', component: () => import(...), nav?: { label, icon, order } }`.

Rules (auto-selected, not user-reviewed):

- Navigation renders only entries that have `nav` set AND whose route exists in the table. Phase 1 therefore has exactly one nav item: "System status" (icon `Activity`, path `/`).
- Routes that are not built are absent: no disabled links, no "Coming soon" items, no greyed-out menu entries, no placeholder pages. Visiting `/login`, `/datasets`, etc. renders the Not Found page.
- Each later phase adds its entries to the registry; nothing else in the shell changes. The registry comment lists the planned groups (Datasets, Chat, Agents, Settings, Admin) as text only, never rendered.
- `auth: 'required'` is recorded in the registry now but not enforced until UI-02 (Phase 2). In Phase 1 the only route (`/`) is `auth: 'none'`.
- Every `component` is `React.lazy` wrapped by one `withLazyRoute` helper providing a `<Suspense>` fallback (route skeleton). `vite build` must emit at least 2 route chunks (status page, not-found) beyond the entry chunk (UI-01 test).

## Interaction Contract: HTTP Client Feedback (UI-03)

The client is one Axios instance in `web/src/services/`, consumed only through `hooks/use-*-request.ts` (TanStack Query). Visual behaviour:

| Event | Behaviour | Toast |
|-------|-----------|-------|
| Request in flight | Component-level loading states only (skeletons). No global top progress bar, no blocking overlay. | none |
| 2xx, envelope `code === 0` | Unwrap `data`; no UI side effect. | none |
| 2xx or non-2xx with envelope `code !== 0` | Reject with `ApiError {code, message, status, requestId?}`; show toast unless the caller passes `{ silent: true }`. | error |
| HTTP 401 | Purge token (`localStorage`), Zustand user store and TanStack query cache; then, only if a `/login` route exists in the registry, navigate to it. Otherwise stay on the page. Show the session toast once (deduped). | error (session) |
| HTTP 5xx without parseable envelope | Reject `ApiError` with synthesized `code: -1`; toast. | error |
| Network failure / timeout (10s default) | Reject `ApiError` with `status: 0`; toast. | error |
| Token present | `Authorization: Bearer <token>` injected on every request; token read from one `authorization` util, never from components. | none |

Toast rules:

- Position bottom-right (top-center below 768px), max 3 visible, newest on top.
- Errors persist 8s, hover pauses, close button always present. Success 4s.
- Dedupe: `toast.error(..., { id: `${status}:${code}:${message}` })` so identical failures update rather than stack.
- `role="status"` / `aria-live="polite"` (sonner default); errors use `aria-live="assertive"`.
- Toast title is fixed per class (table below); description is the server `message` when it is a non-empty string no longer than 160 characters, else the fallback description. Raw stack traces, SQL, or `data` payloads are never shown. Error `code` and `requestId` render in mono 12px as a trailing "Code {code}" line for support.

## State Conventions (apply to every data view from now on, UI-44)

| State | Pattern |
|-------|---------|
| Loading (route) | `RouteSkeleton`: page title bar (24px high, 200px wide) plus three `Skeleton` blocks matching card layout. Shown only if loading exceeds 150ms (avoid flash). No full-screen spinner. |
| Loading (data) | `Skeleton` shaped like the final content; buttons that trigger work show an inline 16px `Loader2` spinner and `aria-busy`, label unchanged. |
| Error (data) | In-place `ErrorState` card: `AlertTriangle` icon (destructive), Heading, one-sentence body, primary "Try again" button re-running the query, optional mono code line. Never only a toast. |
| Error (render / chunk) | Route `ErrorBoundary` renders `ErrorState` with "Reload page" button (`location.reload()`); wrapped in `BareLayout` if the shell itself failed. |
| Empty | `EmptyState` component: 48px lucide icon in `--muted-foreground`, Heading, body (what this is + next step), optional single primary action. Centered, vertical padding 2xl (48px). |
| Not found | `EmptyState` variant with Display "404". |
| Stale/polling | Background refetch is silent; show "Updated {time}" caption in muted Label style. |

Components `EmptyState`, `ErrorState`, `RouteSkeleton`, `PageHeader` live in `web/src/components/` and are the only way later phases render those states.

## The System Status Page (`/`)

Real data, no mocks:

- `PageHeader`: Heading "System status"; right-aligned secondary button "Refresh status" (`RefreshCw` icon, label visible).
- Two `Card`s side by side at `>= 1024px`, stacked below: "Go API" and "Python API". Each card header: engine name (Heading) and an overall `Badge` (Healthy / Degraded / Unreachable). Body: one row per dependency reported by the server health route (`database`, `redis`, `storage`, `doc store`; D-08), label left, status badge right, 12px muted detail (e.g. error text) beneath when unhealthy.
- Source of data: the health/system routes owned by each server per D-08, resolved from `conf/routes.yaml` constants (not hard-coded in components), via `useSystemStatusRequest` (polls every 15s, `retry: 1`). Also shows the `X-API-Source` header value as mono caption to prove which engine answered.
- Badge semantics: Healthy = `--success` dot + text; Degraded = foreground text with `--destructive` dot when any dependency down; Unreachable = destructive text. Status is never conveyed by color alone (dot plus text label).
- Loading: two card skeletons. Error (one engine unreachable): that card shows the in-place error state; the other card renders normally.

## Accessibility and Quality Floor

- WCAG 2.1 AA: all text/background pairs in the Color table meet 4.5:1; focus ring >= 3:1 against adjacent colors in both themes.
- Full keyboard operation: Tab order header -> sidebar -> main; Sheet traps focus; toasts reachable via `F8` (sonner hotkey default) and dismissable with `Esc`.
- Landmarks: `<header>`, `<nav aria-label="Primary">`, `<main id="main">`.
- `prefers-reduced-motion`: disable skeleton pulse and sheet/toast slide; transitions otherwise 150ms ease-out, max 200ms.
- No hard-coded hex values outside `index.css` token definitions; components use semantic tokens only (`bg-background`, `text-muted-foreground`, ...).
- `lang="en"` on `<html>`; document title "devRag" plus page name (`System status - devRag`).
- Touch targets per Spacing exceptions.
