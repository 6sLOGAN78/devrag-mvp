## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Existing tests asserted the exact ratelimit set**
- **Found during:** Task 2 and the full unit run
- **Issue:** `test_render_conf.py::test_cli_renders_phase2_sections` and `test_rate_limit_config.py::test_env_example_defaults_equal_r94` compared the whole `ratelimit` block / all `RATE_LIMIT_*` example lines to the nine R-94 values; the plan itself adds two lines.
- **Fix:** both tests now also expect `provider_test_per_tenant: 10` and `provider_test_window_seconds: 300`. R-94 production numbers are unchanged.
- **Commits:** `2e590d9`, `335b62f`

**2. [Rule 1 - Bug] Dev override variable renamed**
- **Issue:** the plan sets `LLM_ALLOW_PRIVATE_BASE_URLS: ${LLM_ALLOW_PRIVATE_BASE_URLS:-true}` in the dev compose, but the example (and thus `docker/.env` after `--append-missing`) defines `LLM_ALLOW_PRIVATE_BASE_URLS=false`, so the `:-true` default would never apply.
- **Fix:** dev compose uses `${DEV_LLM_ALLOW_PRIVATE_BASE_URLS:-true}` (same pattern as `DEV_RATE_LIMIT_PER_IP_MAX`). Production compose keeps `false`.

**3. [Rule 2 - Missing validation] Extra key and key-id checks**
- `_bounded` got a `lo` parameter for `max_retries` (0..5). The encryption key is rejected if it contains characters outside the URL-safe base64 alphabet (Python's decoder otherwise discards them). `llm.key_id` must match `[A-Za-z0-9]{1,16}` so it can always be sealed into an envelope.
