Go and Python share one itsdangerous-compatible access-token format and one `pbkdf2:sha256:600000` password-hash format, both proven against shared vector files.

## Vectors

- access_token_vectors.json: 23 vectors (accept: valid_fresh, day29, at_max_age, uncompressed, three more fresh tokens, short/whitespace/INVALID_ values which pass the token layer and fail AUTH-08; reject: expired by one second, future, tampered payload/signature/timestamp, wrong secret, no signature, empty, garbage, INVALID_-prefixed token, over-length, non-string payload, bad zlib).
- password_vectors.json: 4 positive (including one Python-generated) and 11 negative (wrong password, scrypt, sha1, iterations below floor and above ceiling, malformed sections, empty hash, empty password, non-ASCII salt, non-numeric iterations).
- go_issued_token.json: 1 Go-issued token (generated by `GO_ISSUED_TOKEN_WRITE=1 go test ./internal/common -run TestGoIssuedTokenFixture`).

## Cross-language results

- Python verifies the Go-issued token with itsdangerous: yes (also rejected with another secret and at +2592001 s; accepted at exactly max age).
- Go verifies every Python/itsdangerous vector: 23/23 (token) and 4/4 positive, 11/11 negative (password).
- Go tests never compare bytes with Python output (zlib streams differ).
