<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client multipart -> server | names, MIME, bytes, sizes and counts are attacker-controlled |
| uploader -> other members' blobs | dedupe links documents to existing blobs |
| server -> MinIO and MySQL | blob and rows must stay consistent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-16-01 | Tampering | path traversal through the file name | mitigate | `normalize_filename` rejects it; keys are server-generated; e2e test with `../../etc/passwd.pdf` and listing before and after |
| T-03-16-02 | Information disclosure | xxh64 collision linking another member's private blob | mitigate | hash plus size lookup, mandatory `streams_equal` before reuse, forged-collision integration test |
| T-03-16-03 | Information disclosure | upload into an inaccessible dataset or probing for dataset ids | mitigate | `authorize_upload` before the body is read; one 404; zero storage calls asserted |
| T-03-16-04 | Denial of service | huge or slow bodies, many files, memory exhaustion | mitigate | Nginx 101m cap, per-request `max_content_length`, body timeout, batch and capacity limits, chunked hashing, one file per SPA request |
| T-03-16-05 | Tampering | orphan blobs after partial failure | mitigate | compensation removes only this request's new keys; fault-injection test |
| T-03-16-06 | Tampering | race between upload dedupe and delete or rename | mitigate | `kb-upload:{dataset_id}` lock and `FOR UPDATE` on the reused file row (completed by plan 03-17) |
| T-03-16-07 | Tampering | disguised content (polyglot, wrong magic) | mitigate | rules from plan 03-15 applied to every file before any write |
| T-03-16-08 | Denial of service | silent empty parse of a malformed multipart | mitigate | zero files is 400 `no_files` (unit test with a truncated body) |
</threat_model>
